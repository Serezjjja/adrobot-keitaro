# Adrobot · Keitaro

Локальное приложение создаёт кампанию с георедиректом на Google и редактирует офферы существующих потоков. Keitaro направляет трафик. SQLite хранит опубликованный снимок, архив, закрепления и незавершённые правки.

## Запуск из чистого клона

Нужны Python 3.12 или новее, uv и Node.js 22.12 или новее с npm. Ниже команды PowerShell. [Установка uv](https://docs.astral.sh/uv/getting-started/installation/)

```powershell
git clone https://github.com/Serezjjja/adrobot-keitaro.git
cd adrobot-keitaro
cd backend
Copy-Item .env.example .env
```

На Linux и macOS используйте `cp .env.example .env`. Откройте админку эмулятора, войдите через GitHub и нажмите **API ключ** в верхней панели. Скопируйте ключ в `KEITARO_API_KEY` в `backend/.env`. В `CAMPAIGN_PREFIX` замените пример `test_ivanov_` на префикс со своей фамилией латиницей. [Админка эмулятора](https://keitaro-for-tests.etolegko.com/admin/)

`KEITARO_BASE_URL` в шаблоне уже указывает на эмулятор. `DATABASE_URL=sqlite:///./adrobot.db` создаёт базу в рабочем каталоге backend. Для другого аккаунта укажите отдельный файл. Ключ читает сервер, а Git игнорирует локальный `.env`.

В первом терминале, из `backend`, выполните

```powershell
uv sync --locked
uv run alembic upgrade head
uv run uvicorn adrobot.main:app --host 127.0.0.1 --port 8000
```

Во втором терминале, из корня клона, выполните

```powershell
cd frontend
npm ci
npm run dev
```

Откройте интерфейс на порту 5173. Vite передаёт запросы `/api` серверу на порту 8000. Для локальной работы запускайте один процесс API. [Интерфейс](http://127.0.0.1:5173) · [Swagger UI](http://127.0.0.1:8000/docs)

## Проверка в браузере

1. В разделе **Новая кампания** введите имя, например `test_ivanov_demo1` для указанного выше префикса, код страны `CA` и ID доступного оффера. Выберите оффер из результатов. Проверьте домен, группу кампаний и источник в **Настройках Keitaro**. Если в справочнике одно значение, форма подставит его. При нескольких выберите нужное. Нажмите **Создать кампанию**.
2. После создания редактор загрузит потоки автоматически. Первым появится редирект страны на Google, затем запасной поток с оффером на 100%. Существующую кампанию можно найти по названию или ID. **Обновить потоки из Keitaro** загружает актуальное состояние (Fetch). Ссылка **Открыть в Keitaro** ведёт к выбранной кампании.
3. Найдите второй оффер по ID, выберите его и нажмите **Добавить оффер**. Получится 50/50. **Отменить изменения** (Cancel) возвращает исходные 100%. Добавьте второй и третий офферы — получится 34/33/33. Добавьте четвёртый — получится 25/25/25/25. Нажмите **Опубликовать в Keitaro** (Push).
4. Добавьте пятый оффер. В черновике появятся пять долей по 20%. Нажмите Cancel — пятый исчезнет, четыре опубликованные доли вернутся к 25%. Теперь удалите один из четырёх, проверьте 34/33/33 и 0% у удалённого, опубликуйте. Верните архивный оффер и снова опубликуйте четыре доли по 25%.
5. Для проверки внешнего изменения откройте **свою** кампанию в Keitaro, уберите две привязки из потока и сохраните оставшимся по 25%. Выполните Fetch. Редактор покажет фактические 25/25 и две архивные строки по 0%. Закрепите долю одного активного оффера и нажмите **Вернуть** у одного архивного. У закреплённого останется 25%, два свободных получат 38% и 37%. Опубликуйте и перечитайте поток.
6. **Убрать** в строке оффера и **Вернуть** в архиве работают с черновиком. **Посмотреть изменения** показывает правки привязок и долей. После Push удалённый оффер остаётся в архиве с 0%. При конфликте **Отменить черновик и обновить** загружает внешние правки после подтверждения. Если результат Push неизвестен, сначала обновите потоки. Редактор сохраняет черновик до сверки.

Adrobot автоматически делит доли между активными офферами. **Закрепить** фиксирует текущий процент. В потоке без черновика закрепление сразу сохраняется в Adrobot и оставляет доли прежними. Чтобы задать свой процент, нажмите на долю, введите целое число от 0 до 100 и нажмите **Сохранить**. Введённая доля закрепится в черновике. Остаток делится поровну между свободными офферами, а целочисленный остаток распределяется по одному процентному пункту в порядке потока.

## Устройство проекта

- `backend/adrobot/main.py` задаёт маршруты FastAPI и время жизни HTTP-клиента. Мутации одного процесса выполняются последовательно. Версия черновика защищает от записи устаревших правок из другой вкладки.
- `keitaro.py` отвечает за HTTP и ошибки Admin API. `campaigns.py` сохраняет попытку создания, создаёт отключённую кампанию, проверяет настройки и оба потока перед включением. После частичной ошибки повторите запрос с теми же данными. Если создание потока ещё не подтверждено, приложение ждёт его появления в Keitaro и сохраняет кампанию отключённой. Для незавершённой кампании, созданной до миграции 0004, сначала проверьте оба потока в админке. Повтор завершённой операции возвращает существующую кампанию, в том числе остановленную оператором. Если исход включения неизвестен и кампания отключена, проверьте её состояние в Keitaro.
- `editor.py` импортирует фактические доли при Fetch. При изменении состава распределяет остаток между свободными активными офферами в стабильном порядке. Для Push нужны хотя бы один активный оффер и сумма 100%. Сервер сверяет текущие данные перед записью и сохраняет признак ожидающей подтверждения публикации в SQLite. Затем отправляет массив офферов выбранного потока и подтверждает запись повторным чтением. Сверка и запись в Keitaro — два отдельных запроса. Внешняя правка между ними может быть перезаписана.
- `db.py` описывает две модели SQLAlchemy 2. Миграции в `backend/migrations` создают таблицы операций создания и снимков потоков. `frontend/src` содержит форму, редактор, карточку потока, поиск офферов и общий клиент API. React отображает рассчитанные сервером доли.

## Автоматические проверки

Из `backend`, после установки и миграций

```powershell
uv run alembic check
uv run ruff check .
uv run ruff format --check .
uv run pytest
```

Из `frontend`, после `npm ci`

```powershell
npm test
npm run build
```

Серверные тесты используют миграции на временной SQLite и контролируемые ответы Keitaro через HTTPX. Проверяются состав и порядок потоков, повторы и частичные ошибки создания, архив, закрепления, восстановление черновика, конфликт и чтение после Push. Для тестов ключ не нужен.

## Работа с ИИ и границы проверки

Codex провёл ревью кода и README, исправил импорт долей при Fetch и зависимость теста от локального префикса. Агенты отдельно проверили создание кампаний, React, сценарий в браузере и исходные материалы. Итоговые проверки выполнялись командами выше.

Браузерный прогон использовал React, настоящий FastAPI и отдельную SQLite с контролируемыми ответами Keitaro. На публичном эмуляторе сверены маршруты OpenAPI и способ получения ключа. Создание собственной кампании и повторное чтение опубликованных потоков на эмуляторе требуют серверного API-ключа. В проверочном окружении ключ отсутствовал.
