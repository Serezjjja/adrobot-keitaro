# Adrobot · Keitaro

Локальное приложение для создания кампаний и управления офферами в Keitaro. Backend использует FastAPI, SQLAlchemy и SQLite, миграции выполняет Alembic. Интерфейс написан на React и JavaScript, сборку делает Vite.

## Запуск

Нужны Python 3.12+, [uv](https://docs.astral.sh/uv/getting-started/installation/) и Node.js 22.12+ с npm. Команды ниже выполняются из корня репозитория в двух терминалах.

**Backend**

```powershell
cd backend
Copy-Item .env.example .env
uv sync --locked
uv run alembic upgrade head
uv run uvicorn adrobot.main:app --host 127.0.0.1 --port 8000
```

На macOS и Linux замените `Copy-Item .env.example .env` на `cp .env.example .env`. Перед запуском отредактируйте `backend/.env`.

| Настройка | Значение |
| --- | --- |
| `KEITARO_BASE_URL` | Адрес эмулятора без `/admin` |
| `KEITARO_API_KEY` | Ключ Admin API из [админки эмулятора](https://keitaro-for-tests.etolegko.com/admin/) после входа через GitHub |
| `CAMPAIGN_PREFIX` | Префикс с вашей фамилией латиницей, например `test_ivanov_` |
| `DATABASE_URL` | Локальный файл SQLite, по умолчанию `sqlite:///./adrobot.db` |

Ключ используется только сервером. Для просмотра API откройте [Swagger UI](http://127.0.0.1:8000/docs). После обновления проекта повторно выполните `uv run alembic upgrade head`.

**Frontend**

```sh
cd frontend
npm ci
npm run dev
```

Откройте [http://127.0.0.1:5173](http://127.0.0.1:5173). Vite передаёт запросы `/api` серверу на порту 8000.

## Как проверить вручную

1. Откройте **Создать кампанию**. Укажите имя с настроенным префиксом, код страны, оффер, а также доступные домен, группу и источник.
2. Созданная кампания открывается в редакторе. Нажмите **Загрузить потоки из Keitaro**. Первый поток перенаправляет посетителей из выбранной страны на Google. Во втором указан выбранный оффер с долей 100%.
3. Добавьте оффер во второй поток. Доли изменятся в черновике. Нажмите **Отменить изменения**, чтобы увидеть исходные значения, затем повторите добавление и нажмите **Опубликовать в Keitaro**.
4. Закрепите долю одного оффера, добавьте или удалите другой и проверьте сумму. Остаток целыми процентами делится между незакреплёнными офферами в порядке потока.
5. Опубликуйте удаление. Оффер останется в локальном архиве с долей 0%. Нажмите **Вернуть** и опубликуйте его снова.
6. Удалите привязку в Keitaro и загрузите потоки повторно. Редактор перенесёт известный оффер в архив. Если его поток уже имеет локальный черновик, редактор сохранит черновик и покажет конфликт.

## Как устроено приложение

- `backend/adrobot/keitaro.py` отправляет запросы к Admin API, проверяет ответы и преобразует ошибки.
- `campaigns.py` создаёт кампанию отключённой, сверяет оба потока и только затем включает её. Запись о создании в SQLite позволяет безопасно повторить запрос после частичной ошибки. Если исход включения неясен и кампания остаётся отключённой, её статус проверяет оператор в Keitaro.
- `editor.py` хранит опубликованный снимок и черновик для каждого потока. Перед заменой массива офферов сверяет его с состоянием в Keitaro. После записи перечитывает поток для подтверждения. Если обнаружен конфликт, сначала отмените правки, затем загрузите поток снова.
- `frontend/src` содержит форму, редактор и общий модуль запросов. React отображает доли из ответа сервера.

Публикация требует активного оффера и суммы долей 100%. Отключённые в Keitaro офферы не участвуют в расчёте. Приложение рассчитано на локальную работу с одним процессом API. Для другого аккаунта Keitaro укажите отдельный файл SQLite.

## Автоматические проверки

В `backend`

```sh
uv run pytest
uv run ruff check .
uv run ruff format --check .
uv run alembic check
```

В `frontend`

```sh
npm test
npm run build
```

Тесты backend используют временную SQLite с настоящими миграциями и контролируемые HTTP-ответы Keitaro. Проверяются создание двух потоков, повтор после частичной ошибки, сохранение черновика, доли, архив, отмена, конфликт и подтверждение публикации после таймаута. Ключ эмулятора для автоматических тестов не нужен.
